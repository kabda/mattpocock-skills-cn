# 阶段边界

**阶段**是会话内的一段工作：追问、实现、QA。定义刻意保持模糊：当你觉得*“好了，这部分完成了”*时，一个阶段就结束了。

**阶段边界**是两个阶段之间的间隙，这项决策只能发生在这里。阶段中途无需决策：继续，或者把剩余工作拆给子 agent。中途压缩会使 agent 丢失思路。

<a id="the-five-options"></a>

## 五种选择

| 选项 | 作用 |
| ------------ | --------------------------------------------------------------- |
| **继续（Continue）** | 留在会话中。完全不切换上下文。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写出可携带的 Markdown 文件，用它在任何地方启动会话。 |
| **子 agent** | 把任务送到独立上下文窗口，取回报告。 |
| **`/compact`** | 压缩当前上下文，用摘要启动新会话。 |

<a id="the-tree"></a>

## 决策树

在边界处从上到下判断。遇到第一个**是**就采用该项。

**1. 能否在当前会话中继续？** 两种情况可以回答是：下一阶段需要把当前阶段当作**一手来源**，或剩余的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k tokens）足以容纳下一阶段。追问 → 实现是典型的“是”：实现需要原样的推理，而不是摘要。继续没有成本，也没有损失，因此在考虑其他选择前先排除它。

**2. 上下文是否与下一步无关？** 当前会话中的所有内容（探索、决策、走不通的路）都可以丢弃吗？如果是，就用 **`/clear`**。它是成本最低的选项：不花时间，归还整个窗口。`/clear` 也不是终止：旧会话仍可恢复。

判断失误的代价是单向的。清空*相关*上下文，就会丢失构建结果背后的**原因**，无论怎样重新阅读 diff，都找不回来。

**3. 是否需要交接？** `/handoff` 的用途很窄。只有以下情况才需要：

- 切换到**新的 harness**（Claude → Codex），
- 转移到**新目录**或仓库，
- 把工作交给**同事**，
- 或在不中断当前工作的前提下，分出**阶段中途**发现的旁支任务。

以上就是全部适用条件。`/handoff` 带来的是**可携带性**：一个能带走的文件。如果没有任何东西需要转移，就不需要它。

**4. 任务能否在 AFK 时完成？** 范围是否足够明确，让你离开键盘后也能无人指导地运行？如果是，就交给**子 agent**，保持本会话不变。自动审查是典型案例：agent 阅读 diff 并汇报，过程中不需要你参与。

**5. 否则，使用 `/compact`。** 上下文相关、harness 相同、目录相同，而且需要你继续参与：决策树最终落在这里，而且经常如此。给它一条指令（`/compact we're going to QA this area`），让摘要保留下一阶段需要的内容。

`/compact` 是**默认选择，而不是最先尝试的选项**。它位于底部，因为前面四个问题对应的选择都更便宜或更精确。如果从这里开始，常见失败就是新会话对摘要抹平的某个决策自信地作出错误判断。

<a id="primary-and-secondary-sources"></a>

## 一手与二手来源

除**继续**之外，每种操作都会把**一手来源**转化为**二手来源**：真实发生过的会话被摘要取代。取舍始终相同：

| 来源 | 信息 | 噪声 | 活动空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（继续） | 完整 | 多 | 少 |
| 二手（`/compact`、`/handoff`） | 有损 | 较少 | 多 |

这就是问题 1 排在最前的原因。只有留下来的成本超过收益时，才付出信息损失的代价。

<a id="these-are-judgement-calls"></a>

## 这些都需要判断

这些问题并不客观：每个都包含个人判断，同一个边界在不同日子可能有两种选择。价值在于**按顺序**提问，而且在边界处提问，不在工作中途提问。
