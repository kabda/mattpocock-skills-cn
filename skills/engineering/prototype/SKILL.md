# 原型

原型是**用来回答一个问题的一次性代码**。问题决定形式。

<a id="pick-a-branch"></a>

## 选择分支

根据用户提示、周围代码，或在用户可联系时询问，确定要回答哪个问题：

- **“这个逻辑／状态模型感觉对吗？”** → [LOGIC.md](LOGIC.md)。构建一个可共享的单 HTML 文件（自由操作按钮，加上分标签页的引导演练），让状态机经历纸面上难以推理的情况，并让非开发者也能操作。
- **“它应该是什么样子？”** → [UI.md](UI.md)。在同一路由上生成几个截然不同的 UI 变体，通过 URL 查询参数和底部悬浮栏切换。

两个分支产出的交付物差异很大，选错就会浪费整个原型。如果问题确实含糊，且联系不到用户，就默认选择与周围代码更匹配的分支（后端模块 → 逻辑；页面或组件 → UI），并在原型顶部说明假设。

<a id="rules-that-apply-to-both"></a>

## 两个分支共同遵守的规则

1. **从第一天起就是一次性的，并明确标注。** 将原型代码放在它实际使用位置附近（被原型化的模块或页面旁），让背景显而易见；但命名要让随意浏览的人也看得出这是原型，不是生产代码。一次性 UI 路由遵守项目已有的路由约定，不要发明新的顶层结构。
2. **运行极其简单。** UI 原型通过项目任务运行器中的一条命令启动：`pnpm <name>`、`python <path>`、`bun <path>` 等。逻辑演示是用户双击就能打开的单个 HTML 文件。无论哪种，启动都无需思考。
3. **默认不持久化。** 状态保存在内存中。持久化是原型正在*检验*的东西，不是它应当依赖的东西。如果问题明确涉及数据库，就使用临时数据库或名称明确标为 "PROTOTYPE, wipe me" 的本地文件。
4. **跳过精修。** 不写测试，不做超出让原型*可运行*所需的错误处理，不做抽象。目的是快速学到东西。
5. **展示状态。** 每次动作后（逻辑）或每次切换变体时（UI），打印或呈现全部相关状态，让用户看到什么变了。
6. **完成后留存。** 将已验证的决策融入真实代码，然后把原型本身作为**一手来源**留存：提交到 main 之外的一次性分支，并在实现 issue 上留下指向该分支的上下文指针。也在 issue 或提交中记录答案（结论及其解决的问题）。主分支只保留已验证的决策。
