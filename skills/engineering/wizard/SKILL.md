# 向导

**向导**是一个 bash 脚本，逐步引导人类完成手动流程；这类流程既不便手工执行，也不便每次都重新向 AI 解释。它打开每个 URL，准确说明该点击和复制什么，捕获值，将其写入正确位置（`.env`、GitHub secrets），每个阶段都确认，并显示还剩多少阶段。它可能配置第三方服务、执行一次性迁移，或将项目从一个状态转移到另一个状态。

[template.sh](template.sh) 已经解决了易用体验：逐阶段进度、确认关卡、跨平台 URL 打开（包括 WSL）、秘密值隐藏输入、幂等 `.env` 插入／更新、`gh secret`/`gh variable` 写入，以及结束摘要。**你的工作只是界定流程并编写各阶段。** `STAGES` 标记上方的库在每个向导中完全相同；一致性正是目的，绝不要手动编辑。

向导默认是临时的：为一次运行而构建，保存到临时用途目录或 `scripts/` 路径，工作完成后删除。只有用户希望仓库中保留可重复的设置路径时，才提交它。

<a id="process"></a>

## 流程

<a id="1-scope-the-procedure"></a>

### 1. 界定流程

弄清人类必须执行的每个手动步骤，以及过程中捕获的每个值。先读仓库，不要毫无准备地提问：

- 设置场景：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用，都是向导必须产出的值）。
- 迁移或状态转换：当前状态、目标状态，以及两者之间的不可逆操作。

然后向用户展示按顺序排列的阶段，以及每个阶段产出的值，并确认：用户可以添加、删除或重新排序。

**完成条件：** 每个阶段都已按顺序命名，对每个捕获值都知道：(a) 人类从哪里获得，(b) 写到哪里（`.env`、GitHub secret、两者，或不写入任何位置；有些阶段只是动作），(c) 是秘密值（隐藏输入）还是公开值。

<a id="2-map-each-stages-journey"></a>

### 2. 梳理各阶段的操作路径

为每个阶段写出人类实际遵循的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、填入哪个变量。例如 "Dashboard → Developers → API keys → Reveal test key → copy"。如果并不知道当前 UI 或准确命令，就说明，并询问用户或查阅文档：绝不要编造可能不存在的步骤。

**完成条件：** 每个阶段都对应陌生人也能遵循的具体说明。

<a id="3-author-the-wizard"></a>

### 3. 编写向导

将 `template.sh` 复制到目标路径。将示例阶段替换为按依赖顺序排列的步骤，每步一个 `stage`。使用库辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。将 `TOTAL_STAGES` 设为你编写的阶段数量。

遵守模板设定的标准：先打开 URL，再询问其中的值；任何秘密值都用 `ask_secret`；每个持久保存的值都用 `write_env`；仅对 CI 确实需要的值使用 `set_secret`；任何不可逆操作之前先 `confirm`。每个 `stage` 都会清屏，只显示当前步骤：每个阶段保持一个聚焦任务，避免人类仍需要的内容滚出屏幕。不要修改标记上方的库。

<a id="4-verify-and-hand-off"></a>

### 4. 验证并交接

- 运行 `bash -n <script>`；如果有 `shellcheck`，也运行它。
- 运行 `chmod +x <script>`。
- 不要自己端到端运行：它会打开浏览器并等待人类输入。改为静态追踪：第 1 步中的每个值都被捕获，并写入该步骤指定的位置；每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用精确匹配。
- 告诉用户如何运行。如果它是可重复的设置路径，就提交并从 README 链接它，让下一个人运行脚本，而不是再次询问 AI。
