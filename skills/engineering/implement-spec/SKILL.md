你已获得一份规格说明。它应有关联工单，描述如何实现。

你应当已经获得 issue 跟踪器信息。没有时，告诉用户运行 `/setup-matt-pocock-skills`。

目标是在同一个**集成分支**实现整份规格说明，并按 issue 跟踪器关闭工作的方式解决每张工单。

工单不是步骤列表，而是存在阻塞关系的**任务图**。因此，始终有一组可以接手的工单构成**前沿**。

与子 agent 的双向沟通应当精简。主要通过**上下文指针**沟通：指向规格说明、工单、研究笔记和先前提交。不要重复已有指针可访问的信息。

尽可能在后台运行**实现子 agent**，获得最大并行度。

<a id="steps"></a>

## 步骤

1. 阅读规格说明和工单，理解任务图。

2. （可选）使用**探索子 agent**开展工单所需的探索：相关代码库文件或外部文档。确保它能保存文件；应把 Markdown 笔记保存在仓库之外、所有后续子 agent 都能访问的目录。这让**实现子 agent**专注实现，而非探索。

3. 创建集成分支。跟踪器通过 PR 关闭工作，或用户要求时，在第 5 步首次合并后创建草稿 PR（没有领先 main 的提交时无法创建），标记为关闭规格说明和工单。

4. 用**实现子 agent**实现各工单，各自在独立 worktree 和分支工作。每个实现子 agent：
   - 开始前确认 worktree 基于集成分支，否则重置到该分支；
   - 通过 Skill 工具调用 `tdd` 实现工单；
   - 报告完成前，将集成分支最新提交合入自己的分支

5. **实现子 agent**完成后，用**合并子 agent**将其工作合入集成分支。

6. 如果可用工单的**前沿**因此变化，启动更多**实现子 agent**处理新工单，以实现最大并发度。

7. 全部工单完成后，通过 Skill 工具对集成分支调用 `code-review`。用一个**实现子 agent**修复审查提出的全部问题。

8. 有草稿 PR 时，标记为可审查。否则按跟踪器关闭工作的方式解决各工单，并报告集成分支。

9. 清理所有**实现子 agent**的 worktree。
