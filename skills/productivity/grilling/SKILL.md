---
name: grilling
description: 围绕计划、决策或想法持续追问用户。当用户希望对自己的思考进行压力测试，或使用任何 'grill' 触发短语时使用。
---

持续访谈用户，直到达成共同理解。将主题映射成一棵**设计树**：每项决策都会分支出依赖它的其他决策。

按**轮次**遍历这棵树。**前沿**由所有前提已经确定的决策组成：也就是*现在*可以提问的问题，无需猜测尚未听到的答案。一轮中问完整个前沿：给每个问题编号，并给出推荐答案。然后等待用户回答，再进入下一轮。

每轮按以下格式呈现：

```
❓ **Q1** - **<问题标题>**: <问题正文，可以有多个段落，包括多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文，可以有多个段落，包括多个选项>

➡️ <你的推荐答案>
```

把每个问题表述成回答 "yes" 就表示接受建议答案。

用户每轮的回答都会重塑这棵树：已确定的决策将前沿向外推进，解锁依赖这些决策的问题。重新计算前沿，提出下一轮问题。如果某个问题的答案依赖于本轮中另一个尚未解决的问题，它就属于*后续*轮次，而不是本轮。

查明*事实*是你的工作，绝不是用户的工作。当前沿中的问题需要环境中的事实（文件系统、工具等）时，派出子 agent 查明；凡是自己能查到的内容，都不要问用户。不要因此阻塞：正在进行的探索属于尚未确定的前提，所以只有依赖它的下游问题需要等待子 agent 汇报；立即提出前沿中的其余问题。*决策*属于用户：把每项决策交给用户，并等待回答。

当前沿为空时，会话结束：设计树的每个分支都已访问，没有任何内容被默默假定。在用户确认已达成共同理解之前，不要据此采取行动。
