这是编写任何由 agent 消费的文档的参考：技能、`AGENTS.md` / `CLAUDE.md`，或通过指针访问的文档。封装方式不同，写作方法相同：相同的着力点让它们可预测，使 agent 每次采用相同的*过程*，而非生成相同的输出。

所写文档是技能时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择及路由技能。

<a id="context-pointers"></a>

## 上下文指针

**上下文指针**是保存在 agent 上下文中的引用，指明某份上下文之外的材料，并写明何时应访问它。技能的 description 是一种指针；`AGENTS.md` 中指向某文档的一行也是同一种东西。决定 agent 何时、以及多可靠地访问材料的是指针的*措辞*，不是目标本身。必需材料藏在措辞薄弱的指针之后，是一个行为波动缺陷：先强化措辞，只有强化无效时才把材料内联。

指针做两件事：说明材料是什么，列出应触发访问的**分支**（分支是文档处理的一种独立情况，因此不同运行会走不同路径）。始终加载的指针中，每个词每一轮都有成本，所以比正文更需要修剪：

- **把引导词放在最前面**：指针是它发挥触发作用的地方。
- **每个分支一个触发条件。** 用同义词重命名同一个分支，等于把一条分支写两次；合并它们，只保留真正不同的分支。
- **删去正文已有的身份说明。**

<a id="the-two-loads"></a>

## 两种负荷

每新增一份文档或一个指针，都在消耗两种预算之一：

- **上下文负荷**是始终加载的材料对 agent 窗口的成本：一行 `AGENTS.md`、技能描述，或任何每一轮都待在上下文里的内容，无论是否触发，都消耗 tokens 和注意力。
- **认知负荷**是人承担的成本：有哪些文档，何时使用哪一份。人就是索引。这不是需要最小化的成本，而是人掌握自主权的代价；在人类判断重要的地方投入，在不重要的地方移除。

只有通过指针才访问的材料，以指针那一行的代价免去了自身上下文负荷；完全没有指针的材料，则全部依赖认知负荷。

<a id="information-hierarchy"></a>

## 信息层级

文档由两类内容构成：**步骤**（agent 按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两者可以自由组合：全是步骤（操作配方）、全是参考（审查规则、本技能），或兼而有之。核心决策是每部分内容在**信息层级**中的位置，这是一架按 agent 需要材料的即时程度排序的梯子：

1. **文件内步骤**是主要层级：agent 按顺序做什么。
2. **文件内参考**按需查阅。它往往是合理的扁平并列集合（审查的所有规则都在同一级），这种安排很好，不是问题信号。
3. **按需披露的参考**放到独立文件中，通过上下文指针访问，仅在指针触发时加载。范围可以从同目录的邻接文件，一直到位于任意位置、可被任何文档指向的完全外部参考。

下放太少，顶层会膨胀；下放太多，又会隐藏 agent 真正需要的材料。这种张力就是决策的全部。

**渐进披露**是沿梯子向下移动（从主文件移出，置于指针之后），以保持顶层清晰。它首先不是 token 优化，而是保护层级的方式。分支是最清楚的披露判据：每个分支都需要的内容内联，只有部分分支会访问的内容放到指针之后。文档有步骤时，本应披露到外部的文件内参考会淹没步骤，让 agent 是否关注它们变得像掷硬币：这既影响可读性，也影响行为波动。

**同处放置**是在文件内部的配套方法：梯子决定内容位于*多深*，同处放置决定它在那里*与什么相邻*。把某概念的定义、规则和注意事项放在同一标题下，而非四处分散，读取一部分时就能带上相邻内容。判据是：文档读起来应像专门写给 agent 的文档。成组内容有这种感觉，散乱内容没有。（这与重复不同：重复把同一个含义写在两处；散乱则把一个含义碎片化到多处。）

这里的失败模式是**蔓延**：即使每行仍有效且唯一，文档也单纯太长。注意力被过多内容摊薄，每加一行就多一行需要保持相关。解决办法是利用层级：把参考放到指针之后，按分支或顺序拆分，使每条路径只携带所需内容。

<a id="steps-and-completion-criteria"></a>

## 步骤与完成标准

每个步骤都以一个**完成标准**结束，即告诉 agent 工作已完成的条件。两项属性使其成为有效着力点：

- **清晰度**：agent 能区分完成与未完成吗？模糊边界（“已经理解”）容易招致**过早完成**：步骤尚未真正完成就结束，注意力转向*把它做完*。眼前可见的后续步骤（**完成后的步骤**）提供拉力；标准的清晰度提供阻力。按顺序防守：**先明确边界**（局部且便宜）；只有边界无法进一步清晰，*且*观察到抢跑时，才拆分序列来隐藏后续步骤。隐藏仅在真正的上下文边界上有效（交接或派发子 agent；内联调用会把后续步骤留在上下文中，什么也没清掉）。
- **要求力度**：要求达到什么程度。“每个修改过的模型都已交代清楚”会迫使深入工作，而“生成变更列表”不会。力度驱动**调查工作**（agent 在工作内部进行的挖掘，隐含于措辞，而非单独列为步骤），也不限于步骤：“应用每条规则”约束一组扁平参考，就像“完成每个步骤”约束序列，因此全是参考的文档仍可设定穷尽性门槛。

最强的标准既可检查，也要求全面覆盖。

<a id="when-to-split"></a>

## 何时拆分

把一份文档拆成两份，会消耗两种负荷之一，因此只有收益足够时才拆：

- **按顺序拆分**：如果完成后的步骤诱使 agent 匆忙结束眼前步骤，就拆开这段序列。让后续步骤不可见，可以促使 agent 对当前任务做更多调查。也要警惕反向操作：合并序列会暴露更多后续步骤，诱发过早完成。
- **按调用拆分**，仅技能适用：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

<a id="leading-words"></a>

## 引导词

**引导词（leading word）**是模型预训练中已存在的紧凑概念，agent 执行文档时借助它思考（_lesson_、_fog of war_、_tracer bullets_）。只重复词，不重复句子，它就会积累分布式定义，调动模型已有先验，以最少 tokens 锚定一整片行为。自造词也可行，前提是定义清楚，但生造词无法调用先验：预训练词免费提供的东西，你必须支付定义 tokens。先找现有词。

它有两次锚定作用。在正文中锚定*执行*：每次出现这个词，agent 都调用同一行为；在扁平参考中，它把注意力聚焦到应查找的某类事物。在指针中锚定*调用*：同一个词出现在提示词、文档和代码库时，agent 会把共享语言与材料关联起来，更可靠地访问它。

寻找用引导词重构的机会：同一组三项特征写了三遍；指针花一句话暗示一个概念。每一处都亟待收敛为单个词：

- “快速、确定、开销低” → _tight_（_tight_ loop，即紧凑循环）。
- “一个你信得过的循环” → _red_，把模糊门槛变成二元可观察状态（循环要么因 bug 变 _red_，要么不会）。

你获得双重收益：更少 tokens，以及让 agent 思考有更清晰的依托。假定每份文档都藏着可被引导词替代的重复表述，去找出来。

这个着力点旁边的失败模式是**否定**：以禁止来引导，会把被禁止的行为带入上下文，使其*更*容易被调用，而非更少。*不要想大象*，结果脑中全是大象；否定只是弱修饰，被强烈激活的概念压过，禁令有一半会被读成执行该行为的指令。提示应写成**正向**：陈述目标行为（“写一行评论”），从而完全不提被禁行为。只有无法正向表达的硬性护栏才值得使用禁止；即便如此，也要搭配正向目标，让注意力落在该做什么上。

<a id="pruning"></a>

## 修剪

- 每个含义保持一个**唯一权威来源**：一个权威位置，使行为变化只需修改一处。**重复**（同一含义出现在多处）增加维护和 token 成本，还会使其在层级中的显著程度超过实际等级。（这恰是引导词的意外反面；引导词刻意重复词，绝不重复含义。）
- **环境**也是权威来源（`package.json` scripts、配置文件、目录布局、`--help` 输出）；复述环境的文档就是**缓存**：一次查询的副本，只有查询昂贵时才值得其负荷。缓存 agent 无法靠查看发现的东西：不成文约定、选择背后的理由、配置不会透露的陷阱。一个文件、一条命令就能查到的内容，留在环境里，那里不会过时。
- 检查每一行的**相关性**：它仍与文档职责有关吗？一行可能从未相关（纯粹说明，或本应移到外部披露的分支），也可能因所描述行为或世界变化而过时。短文档更容易保持相关。缺乏修剪纪律时，默认结局就是**沉积**：添加让人安心，删除让人觉得有风险，于是陈旧层层堆积，直到必须钻透沉积才能找到仍有效的内容。
- 逐句寻找 **no-op（无效指令）**：模型默认已经遵守的指令，付出了负荷，却没增加任何东西。判据（它是否相对默认行为产生变化？）相对于模型，而非读者：两人对某句是否 no-op 意见不同，是对默认行为意见不同，应通过运行文档解决，而非辩论。句子未通过判据时，删除整句，不要只删词。该判据也适用于引导词：弱到不足以改变默认行为的词（agent 本来就算细致，却要求 _be thorough_）也是 no-op；解决办法是更强的词（_relentless_），而非另一种技巧。
