# MISSION.md 格式

`MISSION.md` 位于工作空间根目录，记录用户学习此主题的*原因*。每项教学决策（接下来教什么、呈现哪些资源、设计哪些练习）都应能追溯到此文档。

<a id="template"></a>

## 模板

```md
# Mission: {Topic}

## Why
{1–3 句话。用户追求的具体现实目标。掌握这项技能后，生活或工作会发生什么变化？避免“理解 X”这类抽象表述，追问背后的结果。}

## Success looks like
- {用户将能够做到的一件具体、可观察的事情}
- {另一件具体的事情}
- {…}

## Constraints
- {时间、预算、既有安排、学习偏好，以及任何限定方法的条件}

## Out of scope
- {用户明确表示目前不想探索的相邻主题，以保护最近发展区}
```

<a id="rules"></a>

## 规则

- **每个工作空间一个使命。** 用户想学两件不相关的事，就用两个工作空间。
- **具体胜过抽象。**“十月前跑完半程马拉松”比“更健康”好。“向团队交付一个 Rust CLI”比“学习 Rust”好。
- **质疑含糊表述。** 用户说不清原因时，先访谈，再写任何内容。糟糕的使命比没有使命更差。
- **现实变化时修订。** 使命会变。用户目标变化时更新此文件，不要让过时使命引导未来会话。
- **保持简短。** `MISSION.md` 超过一屏，就不再是指南针，而成了计划。
