# GLOSSARY.md 格式

`GLOSSARY.md` 是本教学工作空间的规范语言。所有讲解、练习和学习记录都应遵守其术语。构建它本身就是学习的一部分：把概念压缩成精炼定义，是用户理解它的证据。

<a id="structure"></a>

## 结构

```md
# {Topic} Glossary

{用一两句话说明本术语表覆盖的主题。}

## Terms

**肌肥大（Hypertrophy）**：
在反复训练中，由机械张力和代谢应激驱动的肌肉生长。
_Avoid_: 增块、练大

**渐进超负荷（Progressive overload）**：
随着时间推移，通过负重、训练量或强度，系统性提高对肌肉的要求。
_Avoid_: 再使劲、升级

**RPE（主观用力程度评分，Rate of Perceived Exertion）**：
用 1–10 分自评一组训练的吃力程度，10 表示力竭，8 表示还能再做两次。
_Avoid_: 用力分数、强度评级
```

<a id="rules"></a>

## 规则

- **仅在用户理解后添加术语。** 术语表记录浓缩知识，不是让用户靠阅读来学习的字典。刚接触概念时，先等他们能正确使用，再收录。
- **有明确取舍。** 同一概念有多个词时，选最合适的，把其余列为应避免的别名。语言由此得以压缩。
- **定义精炼。** 一两句话。定义术语是什么，不是它做什么或如何操作。
- **定义中使用术语表自身的术语。** 术语一旦收录，就在所有地方优先使用，包括其他定义内部。这样以后更容易掌握复杂术语。
- 出现自然分组时，**用子标题分组**（例如 `## Anatomy`、`## Programming`）。术语关联紧密时，平铺列表也可以。
- **明确标出歧义。** 某术语在更广泛领域用得宽泛时，注明本处如何界定：“本工作空间中，'set' 始终指正式训练组；热身组单独记录。”
- **随理解加深而修订。** 用户第一周写的定义，到第六周可能就是错的。原位更新，不留过时条目。
