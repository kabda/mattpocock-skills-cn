# 学习记录格式

学习记录位于 `./learning-records/`，按顺序编号：`0001-slug.md`、`0002-slug.md` 等。延迟创建目录：写第一条记录时再创建。

它们是教学中的 ADR：记录不明显的收获、关键洞见，以及用户陈述的既有知识，用以引导未来会话，并判断最近发展区。

<a id="template"></a>

## 模板

```md
# {所学或所确认内容的简短标题}

{1–3 句话：学到了什么（或确认了哪些既有知识），以及这为什么影响未来会话。}
```

这就是完整格式。一条学习记录可以只有一段。价值在于记录现在已知的*是什么*，以及它*为什么*改变下一步教学，而非填满各个章节。

<a id="optional-sections"></a>

## 可选章节

仅在确有价值时添加。多数记录不需要。

- **Status** frontmatter（`active | superseded by LR-NNNN`）：先前理解被证明错误并被替代时很有用。
- **Evidence**：用户如何展现理解（回答问题、完成练习、引用既有经验）。可能需要复核该判断时很有用。
- **Implications**：为未来会话解锁或排除了什么。不明显时值得记录。

<a id="numbering"></a>

## 编号

扫描 `./learning-records/`，找到现有最大编号，加一。

<a id="when-to-write-a-learning-record"></a>

## 何时写学习记录

以下任一条件成立时就写：

1. **用户展现了对非简单内容的真正理解**：不只是接触过，而是有证据表明能正确使用概念。这为下一步教学设定了新起点。
2. **用户披露既有知识**：“我已经知道 X。”记录下来，避免未来会话重复教，也记录其声称的*深度*。
3. **纠正了误解**：用户此前相信错误内容，现在理解了原因。这类记录价值很高，能预示相关主题未来可能出现的障碍。
4. **学习促使使命变化**：用户发现自己在意的内容与原先以为的不同。交叉链接到 [[MISSION.md]] 并更新它。

<a id="what-does-not-qualify"></a>

### 哪些*不*算

- 只是讲过的材料。讲过不等于学会。等待证据。
- 已在 [[GLOSSARY.md]] 中以术语定义简洁记录的内容。不要重复。
- 逐次会话的活动日志。学习记录不是日记，而是足以影响决策的洞见。

<a id="supersession"></a>

## 替代

后续记录与先前记录矛盾时（用户理解加深或被纠正），将旧记录标记为 `Status: superseded by LR-NNNN`，而非删除。理解演变的历史本身就是有用信号。
