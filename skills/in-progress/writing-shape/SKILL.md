<what-to-do>

用户已提供（或将提供）一份原始素材 Markdown 文件。把它当作输入素材堆：可以是整齐的片段列表、大片无结构文字，也可以是转录稿。格式不重要。做任何其他事前，先从头到尾读完。

然后开展塑形会话，产出独立的文章文档。这是**利用（exploit）**：探索已结束，素材堆已固定；确定结构，再挖掘素材填充它。不要编辑原始素材文件：对本技能来说它只读。

用户未说明文章保存位置时，询问一次并记住路径。

</what-to-do>

<supporting-info>

<a id="the-loop"></a>

## 循环

1. **阅读素材堆。** 完整读取输入文件，形成对内容的整体认识。
2. **确定先备知识。** 与用户确定读者开始前已知什么，即起初就已**奠基**的概念。其他概念必须先由某个内容块奠基，后续内容块才能依赖。参见[奠基](#grounding)。
3. **起草 2–3 个候选开头。** 每个开头应暗含不同论点或角度。全部展示，要求用户选择或组合成混合版本。选定的开头决定后文必须完成什么。
4. **逐段生长。** 开头落定后，问“有了这个开头，读者接下来需要听什么？”从素材堆取材回答。下一个内容块只能依赖已奠基概念，并在落定时为新概念奠基。讨论其形式：段落、列表、表格、提示框、引文、代码块。每种格式选择都应有意识且说得出理由。
5. **边推进边追加到文章文件。** 不要批量攒着写。每个商定的段落或内容块立即写入，让用户看见文章成形。
6. **循环步骤 4，直到文章完成。** 由用户决定何时完成。

<a id="grounding"></a>

## 奠基

每个**概念**都必须先**奠基**，内容块才能依赖它：读者要么本来就知道，要么在先前内容块中接触过。使用尚未奠基概念的内容块会让读者跟丢。单位是概念，而非表达它的词：即使看不到术语，内容块仍可能依赖读者尚不具备的观念。概念有名称（即**术语**）时，奠基意味着同时讲清观念和术语。

概念通过两种方式之一奠基：

- **先备知识**：开头之前就已奠基，由读者带入，起初固定。
- **引入**：某个内容块建立它，从此对文章剩余部分都算已奠基。

持续维护已奠基概念列表。当你问“读者接下来需要听什么”时，下一步所需却尚未奠基的概念，本身就是答案：先在此处或前面的内容块为其奠基，否则不能继续推进。这是[从素材堆取材](#pulling-from-the-pile) 中指出缺口的更高一层：那里是素材缺失，这里是文章缺少基础。

关键在于哪些作为先备知识、哪些在文内奠基。前置要求太多，会把读者挡在外面；文内奠基太多，开头会淹没在定义中。确定先备知识时，与用户商定。

<a id="conversational-feel"></a>

## 对话氛围

这是反过来的追问会话。构思时问“你究竟观察到了什么”，这里问“这篇文章究竟在论证什么，读者需要按什么顺序听到？”提出异议，不放过薄弱转折。段落不能证明其必要性，就删掉。

持续使用这些具体问法：

- “这一段为读者做了什么，是上一段没有做的？”
- “删掉它，会破坏什么？”
- “这里该用段落，还是列表？为什么用段落？”
- “这句话做了两件事：拆开，或选一件。”
- “开头承诺了 X，我们却偏到了 Y。要么重新贯通，要么改开头。”

<a id="pulling-from-the-pile"></a>

## 从素材堆取材

把原始素材当作采石场，而非脚本。取出片段，重写使其适合周围段落，再放进去。一个片段可以拆到多个段落、与另一个合并，或改述。素材堆的职责是供挖掘；文章的职责是读起来声音一致。

文章需要而素材缺少时，明确指出缺口：“这里需要一个例子，素材里没有。现在给我一个，否则删掉这一节。”

<a id="format-arguments-to-actually-have"></a>

## 真正该讨论的格式取舍

选择内容块呈现方式时，与用户明确讨论以下取舍，不要默默决定：

- **段落与列表。** 段落承载论证，列表承载并列项。条目并非真正并列时，段落更好；确实并列时，列表更便于扫读。
- **行内与提示框。** 技巧、警告、旁白放入提示框（`> [!TIP]`、`> [!NOTE]`），但仅限内联会真正打断主论证时。否则留在正文中。
- **表格与重复结构。** 相同字段的同一结构重复 3 次以上，用表格；否则用加粗引导语的段落。
- **引用与改述。** 原话本身是重点时引用；只有观念重要时改述。
- **代码块与内联代码。** 多行、可运行或示例性内容 → 代码块。单个 token 或标识符 → 内联。

<a id="writing-rhythm"></a>

## 写作节奏

每个内容块商定后就追加到文章文件。每次写入前，从磁盘重读文件：用户可能在轮次之间编辑过。绝不盲目覆盖。用户要重写段落时，原位编辑指定段落，其他部分不动。

<a id="out-of-scope"></a>

## 范围之外

- 挖掘素材堆中不存在的新片段（按“从素材堆取材”处理缺口）。
- 编辑原始素材文件。
- 发布、为特定平台排版，或添加用户未要求的 frontmatter。
