你已获得一份规格说明。它应有关联工单，描述如何实现。

目标是在单个分支上通过一个 PR 实现整份规格说明。

工单不是步骤列表，而是存在阻塞关系的**任务图**。因此，始终有一组可以接手的工单构成**前沿**。

与子 agent 的双向沟通应当精简。主要通过**上下文指针**沟通：指向规格说明、工单、研究笔记和先前提交。不要重复已有指针可访问的信息。

尽可能在后台运行**实现子 agent**，以获得**最大并发度**。

<a id="steps"></a>

## 步骤

1. 阅读规格说明和工单，读到足以理解任务图。

2. （可选）使用**探索子 agent**开展工单所需的探索：相关代码库文件或外部文档。确保它能保存文件；应把 Markdown 笔记保存在仓库之外、所有后续子 agent 都能访问的目录。这让**实现子 agent**专注实现，而非探索。

3. 创建分支和 draft PR。PR 应标记为会关闭规格说明 issue 和工单。

4. 使用**实现子 agent**实现每张工单。每个实现子 agent 应在自己的 worktree 和分支中工作。

5. 一个**实现子 agent**完成后，用**合并子 agent**把其工作合并到 PR 分支。

6. 如果可用工单的**前沿**因此变化，启动更多**实现子 agent**处理新工单，以实现最大并发度。

7. 所有工单完成后，对 PR 分支运行 /code-review。用单个**实现子 agent**修复审查提出的全部问题。

8. 将 PR 标记为可审查。

9. 清理所有**实现子 agent**的 worktree。
