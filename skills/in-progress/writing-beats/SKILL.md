<what-to-do>

用户已提供（或将提供）一份包含原始素材的 Markdown 文件。这是**利用（exploit）**：探索已完成，素材堆已固定。选定一条穿过素材的路径，挖掘素材填充每个节拍。

用户未说明文章保存位置时，询问一次并记住路径。

然后，以“自选冒险”的方式逐节拍推进：

1. **确定先备知识。** 任何节拍开始前，与用户确定受众读文章前已经知道什么，即起初就已**奠基**的概念。其他概念必须先由某个节拍奠基，后续节拍才能使用。参见[奠基](#grounding)。
2. 从原始素材中写出 2–3 个候选**起始节拍**，各自代表文章的不同入口。每个只可依赖已奠基概念，并注明它新奠基了哪些概念。写入文章文件前先展示给用户，由用户选一个。预览这个选择会解锁哪些节拍，仿佛让用户提前看见前方一小段路。
3. 用户选定起始节拍后，**只把该节拍**写入文章文件。节拍可以是一句话，也可以是几段，以其自然需要为准。到此停止。
4. 从磁盘重读文章文件，再提供 2–3 个候选**下一节拍**：从文章当前位置可转向的不同方向。每个都必须能从当前已奠基概念集合到达，并注明各自会奠基哪些概念。
5. 循环步骤 3–5，直到文章自然结束。

</what-to-do>

<a id="grounding"></a>

## 奠基

每个**概念**都必须先**奠基**，节拍才能依赖它：受众要么本来就知道，要么在先前节拍中接触过。使用尚未奠基概念的节拍会让读者跟丢，这是整段旅程绝不能做的事。单位是概念，而非表达它的词：即使看不到术语，节拍仍可能依赖读者尚不具备的观念。概念有名称（即**术语**）时，奠基意味着同时讲清观念和术语。

概念通过两种方式之一奠基：

- **先备知识**：第一个节拍前就已奠基，由受众带入，起初固定。
- **引入**：某个节拍建立它，从此以后，对所有后续节拍都算已奠基。

所以每个节拍做两件事：**需要**已有基础的概念，并**奠基**新概念。持续维护已奠基概念列表，每落定一个节拍就更新。

这决定了自选冒险的形态。候选节拍只有在所需概念全部已奠基时才可到达；选择能奠基概念 X 的节拍，就解锁所有等待 X 的节拍。提供下一节拍时，所有候选都必须能从当前已奠基集合到达，并说明各自奠基什么，让用户看见它会开启哪些路径。

关键在于哪些作为先备知识、哪些在文内奠基。前置要求太多，会把缺少基础的读者挡在外面；文内奠基太多，开头节拍会淹没在定义中。确定先备知识时与用户商定；每当一个诱人的节拍依赖尚未奠基概念时，再次审视：要么先加一个奠基节拍，要么把概念提升为先备知识。

<a id="what-is-a-beat"></a>

## 什么是节拍

节拍是旅程中的一次推进，只做一件事：设置场景、落定观点、提出问题、插入旁白、转换角度。然后停下，让读者处于下一节拍可以转向的位置。

节拍大小由需要决定：

- 一句话，如果这次推进仅需如此（“然后，整整三周什么也没发生。”）。
- 一个短段落，如果需要铺垫。
- 多个段落，如果节拍是自包含的片段、论证或例子。

如果一个“节拍”需要五段和三个小标题，那就不是一个节拍，而是两个粘在一起。拆开。

<a id="pulling-from-the-pile"></a>

## 从素材堆取材

从原始素材堆中抽取内容填充节拍。可以改述、拆分、重组或引用。素材堆是采石场。

<a id="ending-the-journey"></a>

## 结束旅程

文章在旅程完成时结束，不是在素材耗尽时结束。大多数素材堆都会剩下未入文的片段。这很好；准备超出所需的原始素材，意义就在这里。

<a id="writing-rhythm"></a>

## 写作节奏

- 每次追加一个节拍，绝不提前写后面的。
- 每次写入前，从磁盘重读文章文件。绝对保留用户编辑。
- 用户大幅修改先前节拍时，让这影响后续走向。
- 用户说 "rewrite that beat"（重写该节拍）或 "go back and try a different beat 3"（回去换一种第三节拍）时，就照做：原位编辑，其他部分不动。
