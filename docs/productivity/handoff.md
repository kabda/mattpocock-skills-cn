<a id="what-it-does"></a>

## 它能做什么

`handoff` 将当前对话压缩为一份**交接文档**：一个 Markdown 文件，写入操作系统临时目录而不是工作区，让一个新的 [agent](https://www.aihero.dev/ai-coding-dictionary/agent) 能读取并接手工作。

它带来的是**可迁移性**，而不是压缩能力。这让本技能的适用范围比听起来更窄。只有工作需要*转移*时才需要文件：转到新的 [agent 运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)、新目录、同事手中，或你想分出去的支线任务。如果没有东西需要转移，就不需要交接：继续当前[会话](https://www.aihero.dev/ai-coding-dictionary/session)、`/clear`、[子 agent](https://www.aihero.dev/ai-coding-dictionary/subagent) 和 `/compact` 足以覆盖普通的阶段结束情况，而且 `/compact` 比本技能更常适用。

<a id="when-to-reach-for-it"></a>

## 何时使用

输入 `/handoff` 调用它；agent 不会自行使用。附上一段说明，指出下一场会话的用途，文档就会为此而写。

触发条件有且只有四种：

| 情况 | 为什么需要文件 |
| --- | --- |
| 切换运行环境（Claude → Codex） | 新环境看不到旧[上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移动到不同目录或仓库 | 最常见的是原型目录 |
| 将工作交给同事 | 对方需要可阅读的材料 |
| 将阶段中途发现的支线任务分出去 | 你继续工作，第二个 agent 接手分支 |

其他情况（同一运行环境、同一目录、完成[追问](https://www.aihero.dev/ai-coding-dictionary/grilling)后转入实现），应当使用 `/compact`。[ask-matt](https://aihero.dev/skills-ask-matt) 提供阶段边界处五种选项的有序决策树。

<a id="branching-is-the-use-people-skip"></a>

## 分支工作是人们忽略的用法

技能描述读起来像会话恢复：写摘要、在这里结束、去那里继续。这样理解时，它就像一个更差的 `/compact`，很容易被略过。真正值得了解的是分支场景。你**留在当前会话**，把积累的上下文复制一份交给并行工作的第二个 agent。

这正是绕道 [prototype](https://aihero.dev/skills-prototype) 时采用的方式。你正在深入讨论设计，遇到一个只有运行代码才能解决的问题，又不想把已经积累的对话用在调查上。交接给原型会话、得到答案、把答案交接回来，然后在原对话中引用。两次转移，一场持续的对话，无需重新解释。

阶段边界处的五种选项中，有三种分别保留不同的东西：`/compact` 保留你的意图，`/clear` 什么也不保留，`/handoff` 保留工作的可迁移性。

<a id="what-travels-and-what-doesnt"></a>

## 什么会转移，什么不会

文档携带当前进行中的工作脉络（正在做什么、为什么、下一步是什么），以及一个 **suggested skills**（建议使用的技能）章节，列出下一位 agent 应当使用的技能。写入前会隐去秘密信息。

它刻意不携带已经写下来的任何内容。规格说明、计划、ADR、issue、提交和 diff 都通过路径或 URL 引用，绝不复制。这样文件保持精简，已确定的细节也只保存在一处，不会变成两份逐渐偏离的版本。

<a id="common-questions"></a>

## 常见问题

**该交接，还是压缩？**
除非有内容需要转移，否则使用 `/compact`。继续同一任务属于压缩场景，而不是交接：同一运行环境、同一目录，而且你仍需要参与，阶段边界决策树最常给出的结论是 `/compact`。`/handoff` 的优势不是摘要更好，而是结果是一个文件，可以带到 `/compact` 无法到达的地方。

**那么 compact、clear 和 handoff 到底有什么区别？**
它们保留的是三种不同的东西。`/compact` 压缩当前上下文，让你在新窗口中继续：意图得以保留。`/clear` 清空窗口，从零开始：当之前的一切都可丢弃时，这是正确选择；如果不是，那就是不可逆的丢失。`/handoff` 写入可携带的文件：工作可以转移到别处继续。注意，三者都会将**[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（实际发生的对话）转为**[二手来源](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（对话的摘要）。只有继续当前会话不会这样做，因此应当最先排除“继续”这个选项。

**交接文件去哪了？**
文件保存在临时目录，这是本技能最常被报告的问题。技能选择 `$TMPDIR`，否则 `/tmp`（Windows 使用 `%TEMP%`），但路径很长。继续前要求返回路径并保存。使用临时目录是刻意的，因为交接文档处于传递中，并非长期维护的交付物。临时目录也不持久，下一问会解释。

**我的交接文件在两场会话之间消失了。**
某些环境会在会话之间清理临时目录（报告中的案例是 Codex），而 `/private/tmp` 会在重启后被清理。如果下一场会话不会在一小时内开始，或将在不同运行环境中开始，文件一写好就自己复制到持久位置。文档*指向*的任何内容也一样：引用其他临时文件的交接材料，可能会让下一位 agent 无法跟进。

**实际要怎么交给下一位 agent？**
开启新会话，并指向路径：读取这个文件，然后继续。请指向文件，不要把摘要粘贴进 shell 命令：如果摘要包含反引号或 `$(...)`，插入 `claude "<summary>"` 时会被破坏；常见失败是静默截断而不是报错，导致新 agent 在不知情的情况下拿到不完整简报。

**这与 `/branch`、`--fork-session` 或内置 `/handoff` 相同吗？**
类似，但不相同；这里并未提供 `/branch` 技能，正式名称是 `/handoff`。fork 继承上下文的精确副本；本技能根据声明的下一项任务，生成*有针对性*的压缩内容并写入文件。如果 fork 能满足需求（同一机器、同一运行环境、同一目录），fork 更省事。一旦目标是 fork 无法到达的地方，文件就更有优势。

**什么时候内容应该放进 `CLAUDE.md`？**
问问它下个月是否仍然成立。`CLAUDE.md` 是项目的长期上下文，无论相关与否，都会加载到每场会话中。交接文档围绕一项正在进行的工作，该工作完成后就失去作用。需要反复解释的事实属于 `CLAUDE.md` 的问题；做了一半的任务属于交接。

**它只记录做什么，没有记录为什么。**
这是合理且反复出现的批评。有两件事有帮助。传入参数（说明下一场会话的用途），让与*该任务*有关的推理保留下来，而不是被压平。还要留意会话从未真正验证、却语气笃定的断言：“X 还没构建”“Y 已经完成”。下一位 agent 会把文档当作契约，不再复查，因此把看法写成事实，会成为后续所有工作的错误前提。交接之前先阅读文档，把任何仅仅假设的内容降低确定性。

**为什么它是技能，而不是斜杠命令？**
两者都可行，适合不同情况。作为技能，它通过与本仓库其他内容相同的安装路径交付和更新，因此可共享；agent 不会自行触发它的限制，由 frontmatter 设置，而不是由实现机制决定。

<a id="its-working-if"></a>

## 如何判断它有效

- 文档只占原对话的一小部分；规格说明、issue 和 diff 以路径和 URL 出现，而不是复制的正文。
- 不打开原会话也能直接阅读，并知道下一步做什么。
- 新 agent 开始工作，而不是要求你重新解释背景。
- 在分支场景中，回来时原会话仍然保持原样。
- 建议技能章节列出的技能，正是你自己也会选择的技能。
- 其中没有密钥、token 或密码。

<a id="where-it-fits"></a>

## 它在流程中的位置

`handoff` 是一个**随时可用的独立工具**，位于会话之间的衔接处，而不是构建流程内部；但其适用范围很窄，坦诚地说，在阶段边界处，你使用它的频率会低于另外四种选项。它最接近的相邻技能是 [prototype](https://aihero.dev/skills-prototype)，因为原型位于独立目录，往返其中恰好就是本技能要处理的转移。在边界处，如果不确定应当继续、清空、交接、委派还是压缩，[ask-matt](https://aihero.dev/skills-ask-matt) 提供这五种选项的排序决策树，并为整套技能指路。
