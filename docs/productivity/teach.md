<a id="what-it-does"></a>

## 功能

`teach` 把运行它的目录变成长驻教学工作空间，通过简短、自包含的 HTML 课程，跨多个[会话](https://www.aihero.dev/ai-coding-dictionary/session) 教你一个主题。

它不靠[模型](https://www.aihero.dev/ai-coding-dictionary/model) 已有知识教学。[参数知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge) 被视为不可信：教学前先寻找高可信资源，记录到 `RESOURCES.md`，并在每节课中引用。另一项结构性事实是它[有状态](https://www.aihero.dev/ai-coding-dictionary/stateful)：使命、资源、课程和所学记录都以文件保存在目录中，因此下一会话从文件接续，而非依赖上次对话剩下的内容。

<a id="when-to-reach-for-it"></a>

## 何时使用

输入 `/teach` 调用；[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自行使用。

当学习本身就是项目时使用：一门语言、一个框架、刚加入的代码库、瑜伽、着色器、认证。它不适合顺带解释一件事。

| 你想要什么 | 使用什么 |
| --- | --- |
| 花几周学习主题，让各次会话逐步积累 | `teach` |
| 在当前会话中解释一个想法 | 就在该会话直接问 |
| agent 上条消息没讲明白，需要重新解释 | [wait-what](https://aihero.dev/skills-wait-what) |
| 打磨已有思考，而非获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 让后台 agent 阅读[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)，留下带引用的文档 | [research](https://aihero.dev/skills-research) |
| 学习追问中冒出的内容，又不中断[追问](https://www.aihero.dev/ai-coding-dictionary/grilling) | 用 [handoff](https://aihero.dev/skills-handoff) 交到教学工作空间，再在那里运行 `teach` |

<a id="prerequisites"></a>

## 前置条件

`teach` 构建的是目录，而非产出单个文件；技能假定每个工作空间只有一个使命，因此应在你愿意专用于单一主题的地方运行。不要放进正在开发的项目：推荐独立仓库，而非全局 `~/.learnings/` 文件夹或工作项目本身。独立仓库也让课程可以提交到版本控制中，团队正是这样共享课程的。

目录中会积累：

| 路径 | 内容 |
| --- | --- |
| `MISSION.md` | 为什么要学。其他内容都依托它；缺少时，`teach` 首先访谈你，直到写清楚 |
| `RESOURCES.md` | 经过筛选的教学来源，分为 Knowledge 和 Wisdom（社区） |
| `lessons/*.html` | 编号课程：主要教学单元 |
| `reference/*.html` | 浓缩速查表、算法、术语表：真正会反复查阅的文档 |
| `learning-records/*.md` | 类似 ADR 的笔记，记录你有证据证明学会的内容，用于决定下一步教什么 |
| `assets/*` | 从共享样式表起步的可复用组件，让所有课程看起来属于同一套课程 |
| `NOTES.md` | 你表达过的教学偏好 |

有两点需注意。术语表适合大多数主题，但随附的 `GLOSSARY-FORMAT.md` 已不再由 `SKILL.md` 链接，因此需主动要求才会得到（[issue #559](https://github.com/mattpocock/skills/issues/559)）。所有文件都落在运行 `/teach` 的目录。

<a id="storage-strength-not-fluency"></a>

## 存储强度，而非流畅度

用来思考的概念是**存储强度**：长期保留能力。与之相对的是**流畅度**，即阅读当下感觉已掌握、一周后却消失的即时回忆。`teach` 通过适宜难度构建前者：提取练习、间隔练习、交错练习。先获取知识，此时难度是敌人，因为会消耗理解所需的工作记忆；然后 `teach` 通过紧凑反馈循环训练技能，此时难度是工具。

两件事决定教什么。**使命**（你想学的具体现实原因）为每节课提供基础；没有它，课程就变得抽象，也无法决定下一步。根据使命和学习记录，`teach` 在你的**最近发展区**内选择下一课：需要付出努力，但不至于超前到无法学会。

这也是技能会提出异议而非一味顺从的原因。需要**智慧**（现实判断）的问题，会先得到尝试性回答，再被指向能检验答案的社区。测验是门槛，不是形式：有用户说“非常感谢”后，被告知练习仍未结束。

<a id="lessons-references-and-components"></a>

## 课程、参考资料与组件

一节**课**是单个自包含 HTML 文件，短到一次能完成，与使命相关，并带来一个具体收获。它引用来源，推荐一个值得亲自阅读的一手来源，并链接到其他课程和参考文档。

值得了解的区别是：课程很少被回看，参考文档则会。所以课程的浓缩精华（语法表、算法、体式序列、术语表）应放在 `reference/`，不要埋在首次介绍它的课程中。

课程由 `assets/` 中的**组件**构建：样式表、测验组件、模拟器、图示辅助工具。默认复用。agent 编写课程前先读取 `assets/`，基于现有内容构建；新内容只要另一节课也能使用，就写成组件，不内联。共享样式表是每个工作空间的第一个组件，让输出不至于成为一堆独立单品。

<a id="common-questions"></a>

## 常见问题

**文件会放在哪里？我的跑到 `~/.claude/skills` 里了。**
保存在运行 `/teach` 的目录（[#377](https://github.com/mattpocock/skills/issues/377)）。

**一直留在同一会话，还是每课开一个新会话？**
三种方式都可行：留在同一会话、在新会话重新调用 `/teach`，或在同一文件夹打开新会话。每节课都是独立调用。延续性来自文件夹，而非对话。常见做法是在工作空间打开新会话，说 `/teach next lesson for <topic>`。

**怎么知道它没有教我编造的内容？**
不能只凭技能的保证来判断。你要读一手来源。`teach` 不可靠到可以免检信任，任何基于 LLM 的技能都做不到。其依据机制（`RESOURCES.md`、每课引用、每课推荐一个一手来源）旨在降低验证成本，而非消除验证需求。失败并非假设：有用户学习二阶魔方时，得到的是无法解开的虚构转动序列。排查这类情况，要看模型、harness、推理强度和来源。记号精确的操作性领域风险最高；代码等输出可立即验证的领域风险最低。

**测验正确答案总是第一个选项。**
多人在 Sonnet、Opus 和 GLM 上确认了此事，仍未修复。`SKILL.md` 现在要求每个答案单词数相同，消除了另一个线索（以前正确答案往往是唯一论述完整的选项），但未规定位置。一位贡献者测试指令层修复，报告九课中 33 次正确答案全部落在 A 位（[#335](https://github.com/mattpocock/skills/issues/335)），说明真正的解决办法应是 `assets/` 中随机排列的测验组件，而非更好的措辞。在发布修复前，不要把答案位置当作有意义的信号。`assets/` 目录由你掌控，因此要求提供渲染时打乱选项的组件，是合理的本地修复。

**它假定我已经知道某些内容，还使用从没定义的术语。**
这是最常见的实质性抱怨。没有评估步骤：`teach` 从使命和学习记录推断水平，但第一会话没有学习记录。有用户在 wayfinder 流程中使用它，直言：“它从未通过追问确定我的起点，因此对我已知的内容作了很多假设。”另一人报告课程依赖未定义术语，还遇到针对其硬件定制的课程只讲硬件能做什么，却不讲不能做什么。两种做法有帮助：在第一条消息中说明已有知识和缺口；课程水平不合适时明确纠正，因为纠正会成为学习记录，引导下一课。显式知识评估步骤是持续存在的功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），并非已发布行为。

**它会安排间隔复习吗？知道什么时候停止教学吗？**
前者不会，后者不可靠。间隔和交错是课程设计原则，但没有任何机制安排复习，也没有 Anki 或日历集成；两者都是反复出现的请求。相关缺口是退出标准：一位用户说，`teach`“擅长制作下一课，却不太擅长判断何时停止，转向复习或真实练习”。如果想复习或训练，而非学习新内容，直接提出；技能不会主动建议切换。

**只适合代码吗？**
不是，而且记录中非编程用途更多：韩语、日语正式语体、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，以及为八岁和十岁孩子制作关于密室逃脱和火蝾螈的可打印书籍。技能没有任何编程专属内容：使命、资源、最近发展区和训练在各领域都一样有效。在代码领域，报告中最突出的用途不是从零学语言，而是熟悉陌生代码库或新团队技术栈。

**应该用哪个模型运行？**
没有标准答案，报告中的差异很大。有人报告更高的[推理强度](https://www.aihero.dev/ai-coding-dictionary/effort) 比中等设置产出的课程明显更好。有用户通过 Copilot CLI 用 Codex 运行同一技能，只得到一张 30 行 HTML 卡片，而 Claude Code 产出了完整课程。它无需修改即可在 Claude Cowork 中运行，前提是组织允许添加技能。课程单薄时，先换模型、[harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或推理强度，再考虑重写提示词。

<a id="its-working-if"></a>

## 有效运行的迹象

- 空目录中，首先访谈你为什么想学，而不是生成课程。
- `RESOURCES.md` 先于课程充实起来，每节课指出一个值得亲自阅读的一手来源。
- 课程论断带有外链。没有引用的课程就是凭记忆教学。
- 一节课一次能完成，并让你会做一件以前不会的事。
- 在文件夹中打开新会话，说“下一课”，会继续课程，而非重头开始。
- `learning-records/` 逐渐增长，课程不再重教你已经证明掌握的内容。
- 课程看起来属于同一套：链接 `assets/` 中的样式表，而非各带一份。
- 需要判断的问题会指向论坛、subreddit 或课堂，不只给一个答案。

<a id="where-it-fits"></a>

## 所处位置

`teach` 是**随时可用的独立技能**。它不是构建链的一步，也不与工程流程共享产物；它拥有自己的目录，只要主题仍在学习，就一直存在。

它真正相邻的技能是 [handoff](https://aihero.dev/skills-handoff)，一起回答“追问遇到不理解的东西怎么办”。不要停止追问来学习，用 `/handoff` 移到教学工作空间，在那里用 `/teach` 学习，再回来从原处继续。如果需要带引用的文档而非课程和记忆保持，相近替代是 [research](https://aihero.dev/skills-research)。不确定选择时，[ask-matt](https://aihero.dev/skills-ask-matt) 路由整套技能。
